# Hamon actions and passive integration

This is an implementation inventory for the 31 registered actions and their runtime dependencies. `src/` remains unchanged. Learning, training, technique metadata and inheritance are mapped separately in [progression](HAMON_PROGRESSION_PARITY.md) and [content](HAMON_CONTENT_PARITY.md). Runtime validation is reported by the project build/GameTest lane; this table alone is not a claim that visual playtesting has passed.

`HamonActionCatalog` preserves original IDs, costs, charging, cooldowns, free-hand requirements and shift variants. `HamonActionService` owns server target acquisition, energy consumption, held leases, continuous phases, cooldowns, protection, movement and synchronized presentation state. Client packets contain an action ID and START/KEEP/RELEASE/CANCEL/LEAP only. Unknown, mixed-case and unlearned IDs fail server validation; target/energy/effect claims are never accepted from the client. Runtime clears on death, disconnect, dimension change and power removal. Missing KEEP expires after15 ticks.

## Entities, effects, persistence and lifecycle

`HamonEntities` preserves original registry dimensions, update intervals, summon/save/fire flags for bubbles, cutters, barrier, turquoise, zoom, snake, Sendo, projectile shield, block charge and afterimage. Turquoise dimensions follow actual radius. Sendo owns independent waves/hit sets and inter-wave hit cooldowns. Shield uses the original fixed8×4 collision plane despite the3×3 registry size. Hypnosis stores previous owner persistently for tameable animals and horses. Charged attachments preserve initial/remaining duration and attribution through chunk reloads/dimension transfer; projectile owner network IDs are refreshed after resolution. Unowned ordinary projectiles continue their source lifespan, while owner-bound arms/snakes require their owner.

`HamonEffects.SHOCK` directly subclasses the shared stun implementation, applies movement/flying/attack modifiers and AI suppression immediately, rejects creative/NoAI, resets creeper fuse, restores AI on removal, and never adds an extra proxy status. Immobilize shares the source attributes and flight/motion suppression. Vanilla has no Forge `SWIM_SPEED`; zero travel input supplies the matching immobilized swimming behavior. Source uncurable SHOCK/HYPNOSIS/IMMOBILIZE/CHEAT_DEATH survive milk. Stun cancels block/item/entity interactions and item pickup. Source colors are preserved.

Source API differences are expressed in Fabric attachments, tracked entity data, registered payloads and narrow mixins. The server remains authoritative. Client renderers/models, colored aura, particles, held sounds and input are implemented by the client adapter and validated in its own lane.

## Source quirks and cross-content boundary

- Cutter instantaneous potion power keeps the source integer `3/16 == 0` behavior.
- Charged splash water computes distance attenuation in the source caller, but the source damage helper ignores its argument; actual full charge damage within radius4 is retained.
- Rebuff cannot counter Stand-source damage unless Hermit Purple is active. This port currently has no Hermit Purple implementation, so Stand-source hits take the source non-counter/protection path. No substitute technique is introduced.
- Plant/block classification uses current block tags/classes because vanilla26.3 removed Forge Material. The predicate retains source logs, living vegetation, mossy/coral names and dead-name exclusions.
